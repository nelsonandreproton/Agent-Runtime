1. What this project does

Purpose

A local-first runtime that loads agent definitions written as Claude Code / Cowork-style markdown subagents, runs them against a local llama.cpp model, and exposes each one over the A2A protocol so external systems — primarily OutSystems ODC — can call them. Tool access (Read, Write, Glob, ...) is satisfied entirely through MCP servers; the runtime implements no tools itself.

5. OutSystems ODC integration — confirmed working, two gotchas

AGENT_RUNTIME_PUBLIC_URL must be externally reachable

The Agent Card's url field is built once at startup from this setting, never inferred from the request. Left at localhost while tunneled (ngrok/Cloudflare Tunnel), ODC's "Get Details" still works (fetches the card) but "Test Connection" fails — it's trying to reach ODC's own localhost, not this machine.

ODC's taskId must be forced empty

ODC's orchestrating LLM sometimes invents a non-UUID taskId on the first turn of a conversation. The A2A SDK hard-rejects any taskId it doesn't already recognize (-32001), which is spec-mandated, not a bug here. Fix is on ODC's side: force that tool parameter to always send empty.

6. Status

Validated end-to-end against a real OutSystems ODC chat agent: ODC fetched an Agent Card, sent a real meeting transcript via message/send, the runtime ran it through the local LLM, and the structured summary rendered back in ODC's chat UI. Seven example agents ship in agents/, several shaped around ODC/Salesforce call patterns. Every request/response and tool call is now logged at INFO level. Not yet built: additional MCP servers beyond filesystem (Tavily, Git, SQLite/Postgres), streaming responses, and authentication on the A2A endpoint itself.
